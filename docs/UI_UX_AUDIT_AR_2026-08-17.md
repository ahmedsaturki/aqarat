# تدقيق واجهة لوحة تشغيل عقارات

## النتيجة التنفيذية

الواجهة الحالية تعمل كـ control plane وظيفي، لكنها أقرب إلى جدول إداري طويل من منتج تشغيل يومي. يوجد تنقل واضح وحواجز وصول أساسية، إلا أن كثافة الأقسام، عرض الجداول، غياب طبقة إجراءات موحدة، وقلة التسلسل البصري تجعل المشغل يحتاج إلى قراءة كثيرة قبل معرفة ما يحتاج إلى فعله.

## الملاحظات المؤكدة من الكود

| المجال | الملاحظة الحالية | الأثر |
|---|---|---|
| الهيكل | كل الأقسام تعيش داخل صفحة HTML واحدة مع دوال render كثيرة | صعوبة توسيع الواجهة وإعادة استخدام المكونات |
| التنقل | قائمة طويلة من عشرة أقسام بلا تجميع أو حالة مختصرة للموبايل | حمل معرفي مرتفع وصعوبة الوصول السريع |
| الملخص | صفحة overview تعرض مؤشرات كثيرة متساوية الأهمية | لا يظهر الإجراء أو الخطر الأهم أولًا |
| الجداول | معظم الجداول بعرض أدنى 760px | تمرير أفقي متكرر على الشاشات الصغيرة |
| الإجراءات | الأفعال inline داخل الجداول ولا توجد نافذة تأكيد أو حالة pending موحدة | احتمال النقر المتكرر وضعف وضوح النتيجة |
| الإدخال | لا توجد واجهات إنشاء وتعديل وأرشفة في الواجهة رغم وجود عقد RPC للعقارات | لوحة التحكم لا تزال جزئيًا للقراءة والتشغيل فقط |
| الحالة | توجد رسائل عامة للنجاح والفشل، لكن لا يوجد skeleton أو empty state متخصص لكل قسم | الإحساس بالبطء والغموض عند عدم وجود بيانات |
| الهوية | يوجد logout وauth mode وRBAC خادمي، لكن الواجهة لا تعرض العضو والدور والصلاحيات الحالية | ضعف الثقة وفهم سبب السماح أو الرفض |
| اللغة | العربية موجودة، لكن عناوين ومؤشرات مثل Leads وJobs وLive وPublic Brand وENFORCED متداخلة | عدم اتساق التجربة للمشغل العربي |
| المرئيات | ألوان جيدة كبداية، لكن التسلسل بين التحذير والمعلومة والإجراء محدود | صعوبة اكتشاف المخاطر التشغيلية |

## اتجاه التصميم المقترح

سيتم اعتماد لوحة تشغيل عربية RTL بطابع **Operations Editorial**: خلفية كحلية هادئة، بطاقات فاتحة، لون برتقالي دافئ للأفعال الأساسية، تركوازي للحالات الصحية، وأحمر محدود للحالات الخطرة. سيتم استخدام شبكة مسافات ثابتة، sidebar قابلة للطي، topbar يوضح السياق والإجراء الرئيسي، وبطاقات مؤشرات مركزة بدل مساواة كل المعلومات.

## ترتيب التنفيذ

يبدأ التنفيذ بإعادة تنظيم الهيكل البصري والـ navigation وطبقة الحالات المشتركة. بعد ذلك تضاف واجهات العقارات والعملاء والإجراءات في drawers أو dialogs قابلة للإغلاق عبر Escape، ثم مركز الأعضاء والصلاحيات والإعدادات، ثم اختبار المرئيات على desktop وmobile وحالات loading/empty/error.

لا تتضمن هذه المرحلة تغييرًا في البيانات أو تجاوزًا للصلاحيات. كل فعل كتابة سيظل يمر عبر API وحارس RBAC وسجل التدقيق، وكل تغيير تشغيلي سيخضع لـ PR وCI ودمج ثم تحقق إنتاجي.
